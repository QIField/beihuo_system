# CRM采购明细爬取脚本使用说明

## 脚本文件
- `crawl_crm_procurement_2024.py` - 爬取从2024年至今的所有CRM采购明细数据

## 功能特性

1. **时间范围**: 自动爬取从2024年1月到当前月的所有采购明细
2. **按月分批**: 按月份分批爬取，避免单次请求数据量过大
3. **断点续爬**: 支持中断后重新运行，已保存的数据会自动去重（基于order_no + number + brand + company）
4. **自动重试**: 网络错误或API失败时自动重试3次
5. **认证刷新**: 检测到认证过期时自动刷新session

## 数据表结构

数据保存到 `crmapp_procurement_history_detail` 表：

| 字段 | 说明 |
|------|------|
| order_no | 订单号 |
| fullname | 客户全称 |
| l_name_zh_default | 产品名称 |
| frey_no | Frey编号 |
| number | 产品编号 |
| brand | 品牌 |
| l_model_zh | 产品型号 |
| purchase_quantity | 采购数量 |
| unit_cost | 单价 |
| create_date | 创建时间 |
| expected_delivery_date | 预计交货日期 |
| year_month | 年月（如2024-01）|
| company | 公司标识（fsbbr）|

## 去重机制

使用 `ON DUPLICATE KEY UPDATE` 实现智能去重：
- 唯一键: `(order_no, number, brand, company)`
- 如果记录已存在，自动更新字段值
- 可以安全地多次运行脚本，不会重复插入

## 注意事项

1. **确保网络畅通**: 脚本需要访问CRM系统和数据库
2. **确保Cookie服务可用**: 脚本依赖 `http://113.45.176.129:8001/get_crm_cookies` 获取认证
3. **首次运行可能较慢**: 数据量大时需要较长时间
4. **建议定期运行**: 可以每月运行一次同步最新数据

## 故障排查

### 认证失败
如果提示认证错误，检查：
- Cookie服务是否正常: `http://113.45.176.129:8001/get_crm_cookies?key=fs`
- 网络是否能访问该服务

### 数据库连接失败
检查：
- 数据库配置是否正确
- 数据库服务是否运行

### 部分月份失败
脚本会记录跳过的月份，可以：
1. 查看错误日志定位问题
2. 修复后重新运行脚本（会自动跳过已完成的月份）
