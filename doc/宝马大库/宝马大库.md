# 宝马大库 — 爬虫字段 ↔ 数据库字段 对照表

> 更新日期: 2026-06-14
> 设计原则:
> 1. 数据库字段名 = 英文，与清洗函数返回的 dict key 完全一致
> 2. 数据库字段值 = 原始爬虫数据（字符串，不做 ×1.13 等换算）
> 3. 采集时间 → 用 MySQL 的 `created_at` / `updated_at` 自动写入，不从爬虫解析
> 4. 选择列（checkbox） → 无业务价值，直接忽略

---

## 三、已移除字段（从旧版到新版的变化）

以下字段在旧版设计中存在，新版已移除:

| 旧字段名 | 原因 |
|---|---|
| `select_value` (对应 "选择" 列) | checkbox 列，无业务价值 |
| `part_display` (显示 "零件号 零件名" 合并文本) | 已有独立的 part_number 和 part_name，不需要合并字段 |
| `part_number_display` (详情表中与 part_number 重复) | 详情表里 "零件 :" 行的值就是 part_number，不需要额外字段 |
| `retail_price` / `retail_price_taxed` (DECIMAL 类型) | 改为 `retail_price_raw` VARCHAR 存储原始字符串 |
| `data_collect_time` (采集时间字符串) | 改用 MySQL 的 `created_at` / `updated_at` 自动维护 |

## 四、派生字段说明（前端/业务层计算）

数据库中存的是原始字符串，**在业务层**（Model 的 `to_web_dict()` 方法）需要解析出数值并计算:

| 派生命名 | 计算方式 | 用途 |
|---|---|---|
| `retail_price_taxed` | `float(正则提取 retail_price_raw 的数值) × 1.13` | 含税零售价 |
| `price_baborui` | `float(正则提取 retail_price_raw 的数值) × 0.87` | 巴博瑞采购价 |
