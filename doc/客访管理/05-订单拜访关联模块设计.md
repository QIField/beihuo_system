## 一、模块定位

回答"**这笔订单是不是跑出来的**"：拜访时间轴每条能看到"已转化订单"（可多张），订单列表每行能看到"关联拜访"。

```
visit_record（status=1，一次拜访）
        │ 1
        ▼ N
visit_order_ref ── orders_id = sales_order_history.deliverysapno（发货金蝶号）
        ├──► M5 订单列表"关联拜访"列（每张订单显示其所属拜访）
        └──► M4 拜访时间轴"已转化订单"标签（每次拜访显示关联的全部订单号）
```

- **锚点**：`orders_id` 字段存发货金蝶号（与 M5"订单号"列展示值同源），字段名沿用 `orders_id`；
- **方向**：一次拜访可挂多张订单；一张订单最多一条关联行（`uk_orders_id`，M5 单值列前提），改绑 = 覆盖该行；
- **取消**：物理删除该行，恢复 = 重新挂一次；
- **无自动匹配**：全部人工维护。

## 二、数据库表 `visit_order_ref`

表说明：客访-订单与拜访关联表（一次拜访关联多张订单，纯人工维护）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 主键，自增 |
| `orders_id` | VARCHAR(255) | 订单标识 = 发货金蝶号 → `sales_order_history.deliverysapno`，非空，**唯一键** |
| `record_id` | BIGINT | 关联拜访记录ID → `visit_record.id`，非空 |
| `matched_by` | VARCHAR(50) | 操作人（登录用户名），非空 |
| `remarks` | VARCHAR(255) | 关联备注（改绑原因、归属说明），可空 |
| `created_at` | DATETIME | 创建时间，默认当前时间 |
| `updated_at` | DATETIME | 默认当前时间并随更新自动变更 |

索引：`uk_orders_id (orders_id)`（一单一次拜访）、`idx_record_id (record_id)`（M4 按拜访反查）。字符集 `utf8mb4 / utf8mb4_unicode_ci`。

```sql
CREATE TABLE IF NOT EXISTS visit_order_ref (
    id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    orders_id VARCHAR(255) NOT NULL COMMENT '订单标识=发货金蝶号(sales_order_history.deliverysapno)',
    record_id BIGINT NOT NULL COMMENT '关联拜访记录ID(visit_record.id)',
    matched_by VARCHAR(50) NOT NULL COMMENT '操作人(登录用户名)',
    remarks VARCHAR(255) DEFAULT NULL COMMENT '关联备注',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_orders_id (orders_id),
    INDEX idx_record_id (record_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='客访-订单与拜访关联表(一次拜访关联多张订单,纯人工维护)';
```

## 三、人工关联与取消（唯一写入渠道）

**指定 / 改绑**：M5 订单行"关联拜访"入口 → 弹层列本客户拜访历史（复用 `GET /new/api/visit/records?amap_customer_id=<POI>`）→ 提交。

```
PUT /new/api/visit/order-refs  body: {orders_id, record_id, remarks?}
校验：
  1. orders_id（发货金蝶号）非空，且在 sales_order_history 中存在
  2. record_id 对应拜访存在且 status=1
  3. 订单所属 CRM 客户 ∈ 该拜访客户当前绑定的 partner_ids 集合（防跨客户错挂）
写入：无行插入 / 有行覆盖 record_id、matched_by、remarks
```

**取消**：`DELETE /new/api/visit/order-refs  body: {orders_id}`，物理删除该行。

**级联**：拜访作废（`status→0`）时物理删除其全部关联行（`idx_record_id` 定位）——作废接口本期未实现，落地时必须同步实现。其余场景（解绑/改绑 CRM 客户、Excel 重复导入、爬虫更新订单）均**不动关联行**。

**权限**：本期登录用户即可（同跟进记录模块口径）。

## 四、展示集成（按页批量装配，不做逐行查询）

| 位置 | 装配 | 输出 |
| --- | --- | --- |
| M5 订单列表（`customer_order_service.get_customer_orders`） | 当前页 `deliverysapno` 集合查关联行 → JOIN `visit_record`（status=1） | `visitRef = {record_id, visit_time, recorder}` 或 `null`（无关联均为 `null`，常规/退货订单均可关联，业务确认 2026-10-24）；标签文案 "MM.DD 拜访"（拜访类型无数据来源，不展示） |
| M4 拜访时间轴（`visit_record_service.get_record_list`） | 当前页 `record_id` 集合查关联行（`idx_record_id`） | `converted`（有≥1条关联即 true，渲染绿色"已转化订单"标签）+ `converted_orders`（发货金蝶号列表，字段自带零成本） |

时间轴不展示关联订单金额/时间（`deliverysapno` 无索引，避免明细大表回查）；如业务要求，先补 `sales_order_history.deliverysapno` 普通索引。

## 五、涉及接口汇总

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| PUT | `/new/api/visit/order-refs` | 指定/改绑（JSON：`orders_id`、`record_id` 必填，`remarks` 选填） |
| DELETE | `/new/api/visit/order-refs` | 取消关联（JSON：`orders_id`，物理删除） |

> 无新增 GET：数据并入现有 `GET /customers/orders`（`visitRef`）与 `GET /records`（`converted` / `converted_orders`）。URL 不带路径参数，订单号走 JSON body（同跟进记录接口口径）。
