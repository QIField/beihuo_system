# 客访管理 - 跟进记录模块设计

> 本文是《[01-主设计文档.md](01-主设计文档.md)》的专项补充，单独说明 `visit_follow_record`（跟进记录）表承载的功能模块。
> **跟进记录与拜访记录（`visit_record`）表级完全独立**：无字段关联、无自动联动、互不引用；时间轴**展示层**将拜访历史以"拜访同步"类型合并进来（只读、不落库）。本文为落地版设计，01 文档 4.4 及 2.1 中"拜访自动同步"相关内容待同步修订（见第七节第 4 条）。
> 对应 01 文档功能模块：**M7 Tab-跟进记录**。
> 代码现状（2026-10-24）：ORM / DAO / 服务 / 接口均未落地，本文先行定契约。

## 一、模块定位

跟进记录是客户详情页的"全渠道沟通流水"：把微信、电话、线上平台、上门等沟通动作记在客户名下，回答"上次跟这个客户联系是什么时候、通过什么方式、聊了什么"。

| 表 | 一句话角色 | 承载功能 |
| -- | -------- | ------ |
| `visit_follow_record` | 客户维度的全渠道沟通流水（纯手动记录） | 时间轴展示、手动新增/编辑/作废 |

**与拜访记录的关系（表级独立 + 展示层合并）：**

| 对比项 | 拜访记录 `visit_record` | 跟进记录 `visit_follow_record` |
| --- | --- | --- |
| 数据来源 | 高德小程序导出 Excel 导入 | 后台手动新增（唯一写入渠道） |
| 承载 Tab | M4 拜访历史 | M7 跟进记录（含拜访历史合并展示） |
| 相互关系 | 以"拜访同步"类型并入跟进时间轴（**只读**：不可编辑/作废、不落跟进表） | 表级无字段关联与联动 |

关系模型：

```
手动新增表单（详情页"新增跟进"）          visit_record (M4 拜访历史，Excel 导入)
        │                                      │ 查询时只读合并，类型=拜访同步
        ▼                                      ▼
visit_follow_record ──► M7 跟进时间轴（手动 + 拜访同步，按时间倒序混排）
        │ amap_customer_id
        ▼
visit_amap_customer（客户锚点，与拜访/绑定同锚）
```

**设计原则：**

1. **只增不物理删**：沟通流水保真实性，作废走 `status=0` 软删；
2. **落库纯手动**：`visit_follow_record` 唯一写入渠道是后台表单；拜访历史仅在查询时合并展示，不落本表；
3. **拜访同步只读**：合并的拜访条目不可编辑/作废，提供"查看完整拜访详情"跳转 M4。

## 二、数据库表 `visit_follow_record`

表说明：客访-跟进记录表（客户全渠道沟通流水，纯手动维护，与拜访记录无关）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 物理主键，自增 |
| `amap_customer_id` | VARCHAR(128) | 高德客户POI编码 → `visit_amap_customer.amap_poi_id`，非空 |
| `channel` | VARCHAR(50) | 跟进渠道：微信/电话/线上平台/上门/其他，非空 |
| `channel_desc` | VARCHAR(100) | 时间轴标题，后端按 `channel` 映射默认值（如"微信沟通"），前端可覆盖 |
| `content` | TEXT | 跟进内容，非空 |
| `follow_time` | DATETIME | 跟进时间，非空，缺省当前时间，允许补录过去时间 |
| `creator_id` | INT | 记录人ID → `crmapp_users.id`（会话无用户ID时为空） |
| `creator_name` | VARCHAR(50) | 记录人（登录用户名 `session.username`），非空 |
| `status` | TINYINT | 1-正常 0-作废，默认 1，非空 |
| `created_at` | DATETIME | 创建时间，默认当前时间 |
| `updated_at` | DATETIME | 更新时间，默认当前时间并随更新自动变更 |

**索引与约束：**

- 主键：`id`
- 普通索引：`idx_amap_customer_time (amap_customer_id, follow_time)` —— 客户时间轴查询
- 无唯一键：纯手动写入无幂等诉求，不做去重约束
- 表字符集：`utf8mb4 / utf8mb4_unicode_ci`

**channel 值域与默认标题映射**（固定枚举，前端下拉，本期不做字典表）：

| channel | 默认 channel_desc（时间轴标题） |
| --- | --- |
| 微信 | 微信沟通 |
| 电话 | 电话沟通 |
| 线上平台 | 线上平台沟通 |
| 上门 | 上门拜访 |
| 其他 | 跟进沟通 |

**status 状态机：**

```
        手动新增
           │ 默认
           ▼
      1 正常 ──作废──► 0 作废
```

| status | 进入条件 | 出口 |
| --- | --- | --- |
| 1 | 手动新增默认 | 作废 → 0 |
| 0 | 手动作废（软删） | 本期不提供恢复 |

## 三、新增 / 编辑 / 作废

### 3.1 新增流程

```
详情页"新增跟进" ──► POST /api/visit/follows
      │ 后端校验：
      │   1. amap_customer_id 存在且 status != 2（无效客户拒绝新增）
      │   2. channel 在枚举值域内
      │   3. content 非空
      │   4. follow_time 缺省取当前时间，允许补录过去时间
      ▼
写入 visit_follow_record（status=1，creator_id/creator_name 取登录用户，
     channel_desc 缺省按映射、可被前端覆盖）
```

### 3.2 编辑与作废

| 操作 | 说明 |
| --- | --- |
| 编辑 | `PUT /api/visit/follows`（JSON body：id + 待更新字段），可改 `channel` / `channel_desc` / `content` / `follow_time`，以 `updated_at` 体现最近变更 |
| 作废 | `PUT /api/visit/follows/void`（JSON body：id），`status` 置 0，时间轴排除 |
| 恢复 | 本期不提供 |

> 全部落库记录均为手动写入，编辑/作废规则统一；时间轴中"拜访同步"条目为拜访历史只读合并，不提供编辑/作废入口。编辑不留操作日志（`visit_operation_log` 在拓展文档）。

## 四、时间轴查询（M7）

**合并查询逻辑**（服务层内存合并，两表保持独立不落库）：

1. 拉取手动跟进（`status=1`，走 `idx_amap_customer_time`，上限 200 条）；
2. 拉取拜访历史（`visit_record.status=1`，同客户 POI，上限 200 条），映射为"拜访同步"类型条目：`channel=拜访同步`、`channel_desc=上门拜访`、`follow_time=visit_time`、`creator_name=recorder`、`is_visit=true`；
3. 两部分按 `follow_time` 倒序混排，切片分页返回；`total` 为合并后总数。

渠道筛选选填（含"拜访同步"：筛选时只取拜访历史；筛选手动渠道时只取跟进表）。手动表单渠道枚举 `channels` 仅返回五项手动值，"拜访同步"仅供筛选。

时间轴条目返回：`id` / `is_visit`（拜访同步条目 true，前端据此隐藏编辑/作废并渲染"查看完整拜访详情"跳转）/ `channel` / `channel_desc` / `content` / `follow_time` / `creator_name`。

分页参数口径同现有服务（`page` / `limit`，limit 上限 200）。

## 五、涉及接口汇总

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/visit/customers/follows` | 跟进时间轴（手动 + 拜访同步合并，query：id=客户物理主键必填，page / limit，channel 筛选选填） |
| POST | `/api/visit/follows` | 新增跟进（JSON：amap_customer_id / channel / content 必填） |
| PUT | `/api/visit/follows` | 编辑跟进（JSON：id 必填 + 待更新字段，部分更新） |
| PUT | `/api/visit/follows/void` | 作废跟进（JSON：id 必填） |

> URL 不带路径参数：客户 id 走 query、跟进记录 id 走 JSON body（同 `visit_detail_api` 口径），客户 id 统一为 `visit_amap_customer` 物理主键，避免透传含逗号的 POI 编码。
