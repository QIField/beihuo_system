# 客访管理 - 主设计文档

> 适用范围：**本期实现**。推迟的表与功能见《[02-拓展设计文档.md](02-拓展设计文档.md)》。

> 数据接入代码后续补充，本文档先定契约与架构
> 数据库要求：MySQL 5.7+（用到 JSON 字段）

## 一、模块定位与本期范围

线下拜访动作（高德小程序）+ CRM 销售数据 的融合视图，回答"业务员有没有在跑客户"和"客户值不值得跑"。

**本期只做这张清单里的表**：

| 类型 | 表                         | 作用                |
| -- | ------------------------- | ----------------- |
| 新增 | `visit_amap_customer`     | 高德端客户             |
| 新增 | `visit_customer_relation` | 高德客户 ↔ CRM客户 手动绑定 |
| 新增 | `visit_record`            | 拜访记录（含照片字段）     |
| 新增 | `visit_follow_record`     | 跟进记录（手动 + 拜访自动同步） |
| 新增 | `visit_order_ref`         | 订单 ↔ 拜访 关联        |
| 已有 | `partner_list`            | CRM客户主档（只读）       |
| 已有 | `sales_order_history`     | 拿货订单（只读）          |

**本期不做**：拜访任务、拜访图片独立表、指标快照表、操作日志表、欠款/信用额度/账期、平台询价指标 → 全部见拓展文档。原型上对应的"创建拜访任务""欠款余额""平台询价次数"等指标本期**不实现或留空**（见第 11 节）；订单 Tab 的"当前欠款"汇总卡已按业务要求**删除**（2026-10-22）。

### 2.1 高德端同步契约（预留，代码后续补）

**客户同步** `POST /api/visit/sync/amap_customer`（幂等键 `amap_poi_id`，已存在则更新可变字段）：

```json
{
    "amap_poi_id": "B0FFH8XXXX",
    "customer_name": "华泰汽车修理厂",
    "address": "五峰四路轻工南六街7号",
    "longitude": 113.1023, "latitude": 23.0105,
    "contact_person": "师傅鹏哥",
    "customer_type": "杂修店", "main_repair_brands": "大众、丰田",
    "staff_count": "8人以上", "station_count": "6工位以上",
    "purchase_channels": "开思|线下", "goods_habit": "其他|原厂|配套",
    "coop_merchants": "原厂开思，品牌线下", "focus_points": "价格|售后|质量",
    "remark": "师傅鹏哥和前台拿货...", "source": "amap_miniapp"
}
```

**拜访同步** `POST /api/visit/sync/record`（幂等键 `external_record_id`，高德端生成且不可变）：

```json
{
    "external_record_id": "amap-20260915-1032-a1b2c3",
    "amap_poi_id": "B0FFH8XXXX",
    "visitor_username": "zhangyw",
    "visit_time": "2026-09-15 10:32:00",
    "visit_type": "新品铺货",
    "checkin_longitude": 113.102355, "checkin_latitude": 23.01062,
    "checkin_address": "五峰四路轻工南六街7号附近",
    "expense_type": "样品费", "expense_amount": 320,
    "content": "主推新款陶瓷刹车片...",
    "images": "https://oss.xxx/1.jpg,https://oss.xxx/2.jpg"
}
```

**同步处理逻辑：**

1. `external_record_id` 已存在 → 直接返回成功（重复推送不产生重复数据）
2. `amap_poi_id` → `visit_amap_customer`；查 `visit_customer_relation` 带出 `partner_id`
3. 围栏校验：签到点与门店经纬度算 haversine 距离，与 `geofence_radius` 比对写 `distance_to_shop` / `out_of_fence`
4. `visitor_username` → `crmapp_users`，**对不上账号时拒绝入库**（不落脏数据）
5. 自动生成一条 `visit_follow_record`（`source=2` 拜访同步）
6. 回写 `visit_amap_customer.last_visit_time`

**安全**：同步接口用固定 Token 鉴权（Header），不走前端登录态。

## 三、核心业务流程

```
【新客户】高德POI采集 → visit_amap_customer(未关联)
      → 业务员上门签到 → visit_record
      → 成交后后台绑定CRM客户 → visit_customer_relation
      → 订单自动匹配到该拜访 → visit_order_ref → 拜访转化率

【老客户】客户列表（超期未拜访）→ 上门签到 → visit_record
      → 自动生成跟进记录 → 订单自动关联

数据流：
高德小程序 ──同步──> visit_amap_customer ──┐
                └──> visit_record ────────┤
                                          │ 手动绑定
partner_list(CRM) ←── visit_customer_relation
      │ customer_id = partner_id
      └──> sales_order_history ──自动匹配──> visit_order_ref ←── visit_record
                        └── 实时聚合 ──> 详情页指标卡
```

## 四、表结构设计

所有新表：`utf8mb4 / utf8mb4_unicode_ci`。⚠️ `partner_list` 是 `utf8mb4_general_ci`，**关联一律走** **`partner_id`（INT）**，字符串匹配需显式 `COLLATE`。

> 设计期曾列出的 `province/city/district` 落地时省略，位置维度筛选使用 `business_circle`。

### 4.2 客户关联表 `visit_customer_relation`

高德客户 ↔ CRM客户，**前端手动绑定**。只存当前有效绑定（**1:N**：一条高德客户可绑定多条 CRM 客户，追加式；反方向 CRM 侧仍为 1:1，一条 CRM 客户仅归属一个高德客户），解绑即删行、不留历史。

表说明：客访-高德客户与CRM客户关联表

| 字段                  | 类型                  | 说明                                               |
| ------------------- | ------------------- | ------------------------------------------------ |
| `id`                | BIGINT              | 主键，自增                                            |
| `amap_customer_id`  | VARCHAR(128) | 高德客户POI编码 → `visit_amap_customer.amap_poi_id`，非空 |
| `partner_id`        | INT          | CRM客户ID → `partner_list.partner_id`，非空           |
| `last_operator`     | VARCHAR(50)  | 最后操作人（绑定/编辑备注），非空                  |
| `bind_remark`       | VARCHAR(255) | 绑定备注（名称差异说明）                       |
| `created_at`        | DATETIME            | 创建时间，默认当前时间（即绑定时间）                    |
| `updated_at`        | DATETIME            | 更新时间，默认当前时间并随更新自动变更                              |

**索引与约束：**

- 主键：`id`
- 唯一键：`uk_partner_id (partner_id)`
- 普通索引：`idx_amap_customer_id (amap_customer_id)`
- 表字符集：`utf8mb4 / utf8mb4_unicode_ci`

**约束说明：**

- `uk_partner_id` 唯一键保证 CRM 侧 1:1：一个 CRM 客户最多被一个高德客户绑定；高德侧为 1:N，同一高德客户可绑定多条 CRM 客户
- 同一对（`amap_customer_id`, `partner_id`）重复绑定 = 更新操作人/备注（幂等，不重复建行）；绑定新的 CRM 客户 = 插入新行
- **解绑 = 物理删除该行**（本期不留绑定历史），无"复用旧行/覆盖痕迹"问题
- 绑定时间不单独存字段，由 `created_at` 承担
- 绑定成功 → `visit_amap_customer.status = 1`；解绑至无任何绑定 → 回置 0

### 4.3 拜访记录表 `visit_record`

对应原型"拜访历史"时间轴。照片本期按 Excel 照片列原样字符串存 `images` TEXT 字段（独立图片表见拓展文档）。

**写入渠道**：本期唯一写入渠道为 **Excel 导入**（高德小程序数据导出 → 后台补录，`source=2`），表字段按导入列设计；2.1 高德同步契约专用字段（签到经纬度、围栏、费用、内容文本）暂不落地，契约实现时再补列。

**Excel 导入列映射：**

| Excel 列 | 落表 |
| --- | --- |
| 记录所属内容 | `visit_amap_customer.customer_name`（按编码建档/更新，本表经 `amap_customer_id` 关联取用，不冗余存储） |
| 记录人 | `recorder` 原样存储（我方业务人员文案，展示用，不参与去重） |
| 记录文字 | `content` TEXT，Excel 原样字符串直接存入，不做结构化 |
| 记录照片（逗号分隔 URL） | `images` TEXT，Excel 原样字符串直接存入，不做结构化 |
| 记录时间 | `visit_time` |
| 记录内容位置编码 | `amap_customer_id`（= `visit_amap_customer.amap_poi_id`） |

表说明：客访-拜访记录表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 主键，自增 |
| `amap_customer_id` | VARCHAR(128) | 高德客户POI编码（Excel"记录内容位置编码"）→ `visit_amap_customer.amap_poi_id`，非空 |
| `recorder` | VARCHAR(50) | 记录人（Excel"记录人"原样，我方业务人员文案，展示用，不参与去重） |
| `visit_time` | DATETIME | 记录时间（Excel"记录时间"），非空 |
| `content` | TEXT | 记录文字，Excel"记录文字"列原样字符串，不做结构化 |
| `images` | TEXT | 记录照片，Excel"记录照片"列原样字符串（逗号分隔 URL），不做结构化 |
| `external_record_id` | VARCHAR(128) | 预留：小程序端记录唯一ID（同步幂等键），可空 |
| `source` | TINYINT | 1-高德小程序同步 2-后台补录（Excel 导入），默认 1，导入服务显式写 2 |
| `status` | TINYINT | 1-正常 0-作废，默认 1 |
| `created_at` | DATETIME | 创建时间，默认当前时间 |
| `updated_at` | DATETIME | 创建时间，默认当前时间并随更新自动变更 |

**索引与约束：**

- 主键：`id`
- 复合唯一键：`uk_visit_dedup (amap_customer_id, visit_time)` —— 幂等去重键（同位置 + 同一秒 = 同一次拜访），列序兼做客户时间轴查询
- 唯一键：`uk_external_record_id (external_record_id)` —— 预留高德同步渠道幂等，与复合键构成两层防线（渠道内防重复推送 / 跨渠道防重复拜访）
- 表字符集：`utf8mb4 / utf8mb4_unicode_ci`

**相对原设计移除的字段**：`visit_type`、`checkin_longitude`、`checkin_latitude`、`checkin_address`、`distance_to_shop`、`out_of_fence`、`expense_type`、`expense_amount`、`content` —— 均为 2.1 高德同步契约专用，Excel 导入无对应数据来源；契约实现时 ALTER 补列（02 拓展文档依赖费用的 `visit_expense_total` 等指标随之顺延）。
另移除 `partner_id`（CRM 关联经 `visit_customer_relation` 桥接查询，不冗余存储）、`visitor_id`（高德记录人为昵称，不映射系统账号）、`converted`（转化标记由订单数据实时统计，不在记录表落库）。

**Excel 导入流程：**

1. 客户档案 upsert：以「记录所属内容」写入 `visit_amap_customer`（冲突时仅更新 `customer_name`，不覆盖地址/坐标等采集字段），无需检查编码是否存在
2. 拜访记录 upsert：不做预查、不区分新增/更新，直接批量写入，由数据库按 `uk_visit_dedup` 自动插入/更新（冲突仅更新 `recorder` / `content` / `images`，`status` / `source` / `created_at` 不被导入覆盖，人工作废、渠道标识保留）
3. `记录人` 原样存 `recorder`（展示用，不映射系统账号、不参与去重）；`记录文字` / `记录照片` 原样字符串直接入库（不做拆分与结构化）；`记录时间` 统一解析为 DATETIME（兼容字符串与 Excel 日期序列）

> 拜访记录**只能作废不能改内容**（保真实性）。

### 4.6 已有表使用说明（只读，不修改）

## 五、指标口径与实时统计

本期无快照表，指标卡**实时聚合**。`sales_order_history` 是**明细级**表，必须先按 `orders_id` 汇总到订单级，否则金额会重复累加。

```sql
-- 订单级聚合基表（金额类指标全部基于它）
SELECT
    orders_id,
    ddno,
    MAX(customer_id)      AS customer_id,
    MAX(create_date)      AS create_date,
    MAX(order_type_id)    AS order_type_id,
    MAX(order_type_name)  AS order_type_name,
    MAX(status)           AS status,
    SUM(total_price)      AS order_amount,
    SUM(cost_price)       AS order_cost
FROM sales_order_history
WHERE customer_id = :partner_id
GROUP BY orders_id, ddno;
```

| 原型指标                      | 取数逻辑                                                                | 本期状态                     |
| ------------------------- | ------------------------------------------------------------------- | ------------------------ |
| 累计拜访次数                    | `COUNT(visit_record WHERE amap_customer_id AND status=1)`           | ✅                        |
| 拜访转化率                     | 经 `visit_order_ref` 实时统计（转化拜访数 / 总拜访数）                              | ✅                        |
| 最近拜访时间                    | `MAX(visit_time)`                                                   | ✅                        |
| 累计拜访投入                    | `SUM(expense_amount)`                                               | ✅                        |
| 累计拿货额                     | 订单级聚合 `SUM(order_amount)`（排除退货类型）                                   | ✅ 退货类型值待确认               |
| 累计订单数 / 客单价               | `COUNT(DISTINCT orders_id)` / 拿货额÷订单数                               | ✅                        |
| 合作起始                      | `MIN(FROM_UNIXTIME(create_date))` 首单日期                              | ✅                        |
| 累计退货金额 / 退货率              | 退货类型订单金额 / 退货额÷拿货额                                                  | ⚠️ 退货类型待确认               |
| 累计利润                      | `SUM(order_amount - order_cost)`                                    | ⚠️ 口径待确认                 |
| 线上订单占比                    | 按绑定 CRM 客户等级 `partner_list.level_name` 拆分：等级为"开思"（或"线上"开头）= 线上，其余 = 线下；1:N 绑定下按客户集合求和（**线上金额 ÷ 总金额**） | ✅ 业务口径已确认（2026-10-21） |
| 近30天 成交次数/金额/毛利/退货/线上占比   | 同上，加 `create_date >= UNIX_TIMESTAMP(NOW() - INTERVAL 30 DAY)`       | ⚠️ 同口径待确认                |
| 流失预警                      | `今天 - MAX(FROM_UNIXTIME(create_date))` 天数 > 阈值（A30/B45/C60/D90，可配置） | ✅ 阈值待业务给数                |
| 拜访状态（30天内已拜访/超期未拜访）       | `last_visit_time >= NOW() - INTERVAL 30 DAY`                        | ✅（"待回访"依赖拜访任务，本期不做）      |
| 欠款余额 / 信用额度 / 账期标准 / 最近回款 | 需 `account_receivable_list`、`customer_quota`                        | ❌ 本期不做 → 拓展文档            |
| 平台询价次数 / 询价转化率            | 需询价数据源                                                              | ❌ 本期不做 → 拓展文档            |
| 原厂件占比                     | **按件数**：常规订单中**品牌名含"原厂"的明细**（如 原厂/原厂国内4s件）quantity 合计 ÷ 常规订单总件数（一条明细的 quantity 即件数） | ✅ 业务口径已确认（2026-10-22） |

**性能**：`idx_customer_id` 已存在，单客户聚合可控。客户列表页若逐行实时算指标会很慢 → 列表页只取必要的几个字段（最近拜访时间、最近订单时间），详情页才做完整聚合。若后续出现性能问题，再引入快照表（拓展文档已设计）。

**订单-拜访自动匹配规则**（任务，建议每小时）：

```
扫描 sales_order_history 中未出现在 visit_order_ref 的订单（按 orders_id 去重）:
  取该客户在订单时间往前7天内最近一次拜访 visit_record
  命中 → INSERT visit_order_ref(relation_type=1, matched_by='system')
  未命中 → 跳过（不强行关联）
人工改绑 → relation_type=2
```

> 拜访转化率由 `visit_order_ref` 实时聚合，不在 `visit_record` 落库 converted 字段。
