# 客访管理 - 拓展设计文档

> 本文档收录**本期未实现**的表、功能与数据源，供后期迭代参考。本期范围见《[01-主设计文档.md](01-主设计文档.md)》。

## 一、推迟的表结构

以下 DDL 已按项目约定设计好，后期需要时直接落地。

### 1.1 拜访任务表 `visit_task`

支撑原型"创建拜访任务"按钮、列表页"待回访"筛选、业务员拜访工作台。

```sql
CREATE TABLE IF NOT EXISTS visit_task (
    id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    task_no VARCHAR(50) NOT NULL COMMENT '任务编号(VT+日期+序号)',
    amap_customer_id VARCHAR(128) NOT NULL COMMENT '目标高德客户POI编码(visit_amap_customer.amap_poi_id)',
    partner_id INT DEFAULT NULL COMMENT '冗余CRM客户ID',
    task_type VARCHAR(50) NOT NULL COMMENT '日常回访/新品铺货/催款对账/新客开发',
    title VARCHAR(255) DEFAULT NULL COMMENT '任务标题',
    assignee_id INT DEFAULT NULL COMMENT '负责人ID -> crmapp_users.id',
    assignee_name VARCHAR(50) DEFAULT NULL COMMENT '负责人姓名(冗余)',
    plan_date DATE NOT NULL COMMENT '计划拜访日期',
    status TINYINT NOT NULL DEFAULT 0 COMMENT '0-待执行 1-已完成 2-已取消 3-已过期',
    done_record_id BIGINT DEFAULT NULL COMMENT '完成后关联的拜访记录ID',
    remark VARCHAR(500) DEFAULT NULL COMMENT '备注',
    creator_id INT DEFAULT NULL COMMENT '创建人ID',
    creator_name VARCHAR(50) DEFAULT NULL COMMENT '创建人姓名',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_task_no (task_no),
    INDEX idx_amap_customer (amap_customer_id),
    INDEX idx_assignee_status (assignee_id, status, plan_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='客访-拜访任务表';
```

配套逻辑：拜访同步时若有同客户+同负责人+`plan_date <= 今天` 的待执行任务 → 自动标记完成并回填 `done_record_id`；每日任务把超期任务置为已过期。

### 1.2 拜访图片附件表 `visit_record_image`

本期照片存 `visit_record.images` TEXT（Excel 原样字符串，不做结构化）；当出现"图片分类管理、按类型检索、独立权限控制、批量导出"需求时改为独立表。

```sql
CREATE TABLE IF NOT EXISTS visit_record_image (
    id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    record_id BIGINT NOT NULL COMMENT '拜访记录ID',
    image_url VARCHAR(500) NOT NULL COMMENT '图片URL或OSS Key',
    image_type VARCHAR(50) DEFAULT NULL COMMENT '门店门头/货架陈列/样品照/工位现场/其他',
    sort INT DEFAULT 0 COMMENT '排序',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (id),
    INDEX idx_record_id (record_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='客访-拜访图片附件表';
```

迁移方式：从 `visit_record.images` 文本按逗号拆分 URL 插入，随后删除该字段。

### 1.3 客户统计快照表 `visit_customer_stats`

本期指标卡实时聚合。当客户量增长导致详情页/列表页变慢时启用，改为**每日全量重算**（参考 `oe_parts_sales` 的备份→写入→校验→替换→清理流程）。

| 字段组 | 字段 |
|--------|------|
| 维度 | `stat_date`(DATE)、`partner_id`(可空)、`amap_customer_id`(可空，二选一非空) |
| 拜访 | `visit_total_count`、`converted_visit_count`、`visit_convert_rate`、`last_visit_time`、`visit_expense_total` |
| 销售 | `sales_total`、`sales_year`、`sales_month`、`profit_total`、`refund_total`、`refund_rate`、`online_sales_rate`、`last_order_date`、`days_since_last_order` |
| 近30天 | `inquiry_count_30d`、`inquiry_convert_rate_30d`、`online_orders_30d`、`offline_orders_30d`、`sales_30d`、`online_sales_rate_30d`、`profit_30d`、`refund_30d` |
| 派生 | `arrears_balance`、`visit_status`(0-超期未拜访 1-30天内已拜访 2-待回访)、`lost_warning` |

```sql
CREATE TABLE IF NOT EXISTS visit_customer_stats (
    id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    stat_date DATE NOT NULL COMMENT '统计日期',
    partner_id INT DEFAULT NULL COMMENT 'CRM客户ID',
    amap_customer_id VARCHAR(128) DEFAULT NULL COMMENT '高德客户POI编码(visit_amap_customer.amap_poi_id)',
    visit_total_count INT DEFAULT 0 COMMENT '累计拜访次数',
    converted_visit_count INT DEFAULT 0 COMMENT '已转化拜访次数',
    visit_convert_rate DECIMAL(5, 4) DEFAULT NULL COMMENT '拜访转化率',
    last_visit_time DATETIME DEFAULT NULL COMMENT '最近拜访时间',
    visit_expense_total DECIMAL(12, 2) DEFAULT 0 COMMENT '累计拜访投入',
    sales_total DECIMAL(18, 2) DEFAULT 0 COMMENT '累计拿货额',
    sales_year DECIMAL(18, 2) DEFAULT 0 COMMENT '本年销售额',
    sales_month DECIMAL(18, 2) DEFAULT 0 COMMENT '本月销售额',
    profit_total DECIMAL(18, 2) DEFAULT 0 COMMENT '累计利润',
    refund_total DECIMAL(18, 2) DEFAULT 0 COMMENT '累计退货金额',
    refund_rate DECIMAL(5, 4) DEFAULT NULL COMMENT '退货率',
    online_sales_rate DECIMAL(5, 4) DEFAULT NULL COMMENT '线上订单占比',
    last_order_date DATETIME DEFAULT NULL COMMENT '最近成交时间',
    days_since_last_order INT DEFAULT NULL COMMENT '距最近下单天数',
    arrears_balance DECIMAL(18, 2) DEFAULT NULL COMMENT '欠款余额',
    inquiry_count_30d INT DEFAULT 0 COMMENT '近30天平台询价次数',
    inquiry_convert_rate_30d DECIMAL(5, 4) DEFAULT NULL COMMENT '近30天询价转化率',
    online_orders_30d INT DEFAULT 0 COMMENT '近30天线上成交次数',
    offline_orders_30d INT DEFAULT 0 COMMENT '近30天线下成交次数',
    sales_30d DECIMAL(18, 2) DEFAULT 0 COMMENT '近30天成交金额',
    online_sales_rate_30d DECIMAL(5, 4) DEFAULT NULL COMMENT '近30天线上占比',
    profit_30d DECIMAL(18, 2) DEFAULT 0 COMMENT '近30天毛利额',
    refund_30d DECIMAL(18, 2) DEFAULT 0 COMMENT '近30天退货金额',
    visit_status TINYINT DEFAULT NULL COMMENT '0-超期未拜访 1-30天内已拜访 2-待回访',
    lost_warning TINYINT DEFAULT 0 COMMENT '流失预警 0-否 1-是',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_stat_partner (stat_date, partner_id),
    UNIQUE KEY uk_stat_amap (stat_date, amap_customer_id),
    INDEX idx_lost_warning (stat_date, lost_warning)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='客访-客户统计快照表';
```

配套任务：`visit_stats_daily_refresh` 每日 04:00~05:00（**避开 03:00 销售爬虫**）。

### 1.4 操作日志表 `visit_operation_log`

支撑原型时间轴中的"[编辑位置] 校准了门店经纬度，围栏半径调整为80米"，以及绑定/解绑、订单关联调整的审计追溯。

```sql
CREATE TABLE IF NOT EXISTS visit_operation_log (
    id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    target_type VARCHAR(30) NOT NULL COMMENT 'customer/relation/visit_record/order_ref',
    target_id BIGINT NOT NULL COMMENT '对象ID',
    action VARCHAR(50) NOT NULL COMMENT 'edit_location/edit_info/bind/unbind/adjust_order_ref/void',
    detail JSON DEFAULT NULL COMMENT '变更明细(字段级before/after)',
    operator_id INT DEFAULT NULL COMMENT '操作人ID',
    operator_name VARCHAR(50) DEFAULT NULL COMMENT '操作人姓名',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '操作时间',
    PRIMARY KEY (id),
    INDEX idx_target (target_type, target_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='客访-操作日志表';
```

> 本期 `visit_customer_relation` 解绑即物理删行、不留绑定历史（业务确认不需要）；如需绑定/解绑审计，可由本表（操作日志）补齐，该表同时覆盖"客户资料编辑"这类字段级变更追溯。

| 流失预警任务化 | 快照表 | 本期为实时计算标签；后期可做"预警客户清单 + 消息推送"（参考 `message_push`） |
| 高级筛选 | 快照表 | 组合条件（等级+渠道+拜访状态+流失）+ 保存筛选方案 |

## 三、推迟的数据源（对应原型上本期不实现的指标）

### 3.1 欠款 / 信用额度 / 账期（客户额度管理模块）

| 数据 | 已有表 | 用途 |
|------|--------|------|
| 应收账款 | `account_receivable_list` | 欠款余额、当前欠款、最近回款、逾期金额（原型"逾期 ¥12300"） |
| 授信额度 | `customer_quota` | 信用额度、额度状态 |

**已知可用桥接字段**：`account_receivable_list.customer_code = partner_list.remenber_code`，ORM 已有 `backfill_partner_id` 回填逻辑 → 后期按 `partner_id` 关联即可。
**注意**：`account_receivable_list` 数据来自 **Excel 手工导入**（无定时任务），时效性取决于运营导入频率，指标需标注"数据截止时间"。

### 3.2 平台询价（询价次数 / 询价转化率）

- 数据源待定：开思平台询价记录 或 微信询价 `wechat_daily_quote_detail`。
- **口径风险**：`wechat_daily_quote_detail.inquiry_customer` 是**客户名称字符串**而非ID，与 `partner_list.fullname` 匹配会漏统/错统（同一客户多种叫法）。
- 建议：后期要么要求业务规范客户命名，要么在询价表补 `partner_id` 回填逻辑（同欠款表思路）。

### 3.3 原厂件占比

需品牌/原厂属性字典（当前只有 `sales_order_history.brand_name` 字符串），需业务方定义"原厂件"品牌清单或接入产品属性表。

## 四、后期需一并处理的技术风险

1. **Collation**：`partner_list` 为 `utf8mb4_general_ci`，新表为 `utf8mb4_unicode_ci`；关联一律走 `partner_id`（INT），按名称匹配时显式 `COLLATE`，否则报 `Illegal mix of collations`。
2. **时间字段混用**：`sales_order_history.create_date`、`partner_list.create_time` 是**秒级 INT 时间戳**，新表用 DATETIME，统计 SQL 统一 `FROM_UNIXTIME()` / `UNIX_TIMESTAMP()` 转换（注意不是毫秒）。
3. **`partner_id` 失效**：`partner_list` 每周二全量重拉，CRM 侧删除/重建客户会使已绑定关系指向失效 ID；建议加定期校验任务，失效关系标记异常并在前端提示重新绑定。
4. **订单金额去重**：`sales_order_history` 为明细级（主键 `orders_items_id`），任何金额汇总必须先按 `orders_id/ddno` 聚合，否则重复累加。
5. **同步接口鉴权**：Token 长期有效存在泄露风险，后期可升级为签名 + 时间戳 + IP 白名单。
6. **打卡真实性**：围栏校验本期只作标记（`out_of_fence`），后期可加"超围栏需审核/不允许提交"的策略开关；另需确认同一业务员同一天同客户是否允许多次签到（防重复打卡）。
