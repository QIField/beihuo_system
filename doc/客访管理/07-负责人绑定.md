# 客访管理 - 负责人绑定模块设计



## 功能要求

添加一个关联表，将**负责人**（负责人是系统用户，即 `crmapp_users` 中的账号）与**高德客户**（`visit_amap_customer`）进行绑定关联。

- 关系模型：**多对多** —— 一条高德客户可绑定多个负责人；一个负责人可负责多条高德客户
- 绑定只存当前有效关系，解绑即物理删除该行、不留历史
- 用途：
  - 客户详情页展示"负责人"列表
  - 客户列表按负责人筛选（谁负责的客户一目了然）
  - 作为后续数据权限的基础（业务员只看自己负责的客户）

## 数据库设计

新增表：`visit_customer_owner`（客访-高德客户负责人关联表），多对多纯关联表。

```
visit_amap_customer (M) ── visit_customer_owner ── (N) crmapp_users
        id                 visit_amap_customer_id        user_id
```

表说明：客访-高德客户与负责人关联表

| 字段                       | 类型       | 说明                           |
| ------------------------ | -------- | ---------------------------- |
| `id`                     | INT      | 主键，自增                        |
| `visit_amap_customer_id` | INT      | visit\_amap\_customer的id     |
| `user_id`                | INT      | 负责人ID → `crmapp_users.id`，非空 |
| `operator`               | INT      | 操作用户id，非空                    |
| `created_at`             | DATETIME | 创建时间，默认当前时间（即绑定时间）           |
| `updated_at`             | DATETIME | 更新时间，默认当前时间并随更新自动变更          |

**索引与约束：**

- 主键：`id`
- 唯一键：`uk_customer_user (visit_amap_customer_id, user_id)` —— 同一对（客户+负责人）不重复绑定
- 普通索引：`idx_user_id (user_id)` —— 按负责人反查客户列表
- 表字符集：`utf8mb4 / utf8mb4_unicode_ci`（与 `crmapp_users` 一致）





## 功能实现

### 接口设计

沿用 `visit_bp`（`/api/visit` 前缀）：

| 方法     | 路径                                             | 说明                                             |
| ------ | ---------------------------------------------- | ---------------------------------------------- |
| GET    | `/api/visit/customer-owners?visit_amap_customer_id=` | 查某客户的负责人列表（详情页展示）                        |
| POST   | `/api/visit/customer-owners`                         | 绑定负责人 `{ visit_amap_customer_id, user_id }` |
| DELETE | `/api/visit/customer-owners`                         | 解绑 `{ visit_amap_customer_id, user_id }`（请求体传参，物理删除） |

`visit_amap_customer_id` 传 `visit_amap_customer.id`（物理主键，与详情页 `?id=` 口径一致）。



### 绑定流程

```
客户详情页"负责人"区域 → 添加负责人（弹层选用户，来源 crmapp_users）
      │
      ▼
POST /api/visit/customer-owners
      │ 后端校验：
      │   1. visit_amap_customer_id 在 visit_amap_customer 中存在且 status != 2（无效客户不可绑）
      │   2. user_id 在 crmapp_users 中存在
      │   3. 同对已绑定 → 幂等返回成功（不重复建行）
      ▼
INSERT visit_customer_owner（operator 取当前登录用户 id，捕获 Duplicate entry 兜底并发）
```

### 解绑流程

```
DELETE /api/visit/customer-owners
   物理删除该行（uk_customer_user 定位唯一行）
```

解绑后可随时重新绑定。

### 查询场景

| 场景                                           | 走的索引                                       |
| -------------------------------------------- | ------------------------------------------ |
| 客户详列表添加一个负责人列（联 `crmapp_users` 取姓名/用户名） 使用逗号分割展示,如“张三,李四” ，在负责人列里面有一个按钮可以弹窗绑定负责人   | `uk_customer_user` 最左前缀 `visit_amap_customer_id` |
| 客户详情添加一个负责人展示（联 `crmapp_users` 取姓名/用户名）  使用逗号分割展示,如“张三,李四”      | `uk_customer_user` 最左前缀 `visit_amap_customer_id` |

### 注意事项

1. **`user_id`** **存在性校验**：`crmapp_users` 是系统自有表，不存在爬虫失效问题，但仍需校验后写入，防脏数据。
2. **`operator` 取当前登录用户 id**（session 中的用户），不从请求参数传入。
3. **多负责人语义**：绑定多对多，客户列表"负责人"列展示多人（顿号分隔），筛选按任一命中。
