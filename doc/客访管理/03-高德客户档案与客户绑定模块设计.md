# 客访管理 - 高德客户档案与客户绑定模块设计

> 本文是《[01-主设计文档.md](01-主设计文档.md)》的专项补充，单独说明 `visit_amap_customer`（高德客户档案）与 `visit_customer_relation`（客户绑定）两表承载的功能模块。字段 DDL 级定义以 01 文档第四章为准，本文不重复罗列。
> 对应 01 文档功能模块：**M1 客户列表**（高德侧数据源）、**M6 客户详情-基础档案**（左半）、**M8 客户绑定**、**M9 数据接入**（客户同步部分）。

## 一、模块定位

客访体系里，所有拜访记录、跟进记录、指标统计的挂载锚点都是**高德客户**，而 CRM 侧的订单、客户等级、片区等数据锚点是 `partner_list`。这两个表分别解决：

| 表 | 一句话角色 | 承载功能 |
| -- | -------- | ------ |
| `visit_amap_customer` | 客访体系的"客户锚点" | POI 采集落库、手工新建、未关联池、档案编辑 |
| `visit_customer_relation` | 高德 ↔ CRM 的"翻译器" | 手动绑定/解绑、追加关联 |

关系模型：

```
visit_amap_customer (1) ──当前绑定── (0..N) partner_list
        │                                    │
        └── visit_customer_relation 只存当前有效绑定（解绑即删行，不留历史）
            高德侧 1:N：一条高德客户可绑定多条 CRM 客户（idx_amap_customer_id 普通索引）
            CRM 侧 1:1：一条 CRM 客户仅归属一个高德客户（uk_partner_id 唯一键保证）
```

## 二、`visit_amap_customer`：高德客户档案

### 2.1 数据来源

| 通道 | 入口 | 说明 |
| --- | --- | --- |
| 高德小程序采集（主通道） | `POST /api/visit/sync/amap_customer`（Token 鉴权） | 幂等键 `amap_poi_id`，已存在则更新可变字段 |
| 后台手工新建（补充通道） | 页面录入 | 无真实 POI，后端生成伪编码 `MANUAL_<uuid>` 作主键，满足"纯CRM客户也纳入拜访管理"的诉求 |

### 2.2 幂等与防重

- `amap_poi_id` 即主键：真实 POI 全局唯一，重复推送由同步端做"存在即更新"；数据库层兜底防并发重复插入。
- 手工新建客户用 `MANUAL_<uuid>` 伪编码，与真实 POI 天然不冲突；这类客户的录入防重靠业务校验（名称+地址）。

### 2.3 状态机（`status`）

```
            采集落库 / 手工新建
                   │ 默认
                   ▼
              ┌─ 0 未关联CRM ──绑定成功──► 1 已关联CRM
              │                            │
        标记无效                          解绑
              │                            │
              ▼                            ▼
         2 无效 ◄─────────────────────── 0
```

| status | 含义 | 进入条件 | 出口 |
| ------ | --- | ------ | --- |
| 0 | 未关联CRM | 采集/新建默认值 | 绑定成功 → 1；人工标记 → 2 |
| 1 | 已关联CRM | 绑定成功（由绑定事务回写） | 解绑 → 0 |
| 2 | 无效 | 人工标记（闭店/重复采集/错误采集） | 本期不参与列表、不可绑定 |

### 2.4 冗余字段的维护责任

| 字段 | 维护方 | 时机 |
| --- | --- | --- |
| `last_visit_time` | 系统 | 拜访同步/后台补录成功后回写 `MAX(visit_time)`；驱动列表"30天内已拜访/超期未拜访" |
| `visit_time` | 高德端 | 采集原文透传，只读展示，系统不回写 |
| `color` / `tag` / `folder` / `business_circle` 等 | 高德端 | 采集原文透传，后台可编辑 |

### 2.5 承载页面

- **客户列表（M1）**：高德名/CRM名双名称、区域（`district`）、客户类型、拜访状态（基于 `last_visit_time`）筛选。
- **详情页左半基础档案（M6）**：采集信息原文展示。
- **未关联CRM客户池**：`GET /api/visit/amap-customers/unbound`（`status=0`），绑定的入口。
- **档案编辑**：`PUT /api/visit/amap-customers/<id>`，可改经纬度、围栏半径等（围栏校验在拜访同步时使用）。

## 三、`visit_customer_relation`：客户绑定

### 3.1 为什么需要独立的绑定表

1. **`partner_list` 每周二全量刷新**，CRM 侧客户可能被删除 → 绑定关系必须独立留存，且所有使用 `partner_id` 的场景要做存在性校验（见 01 文档第十节）。
2. **名称天然不一致**：高德 POI 名（如"华泰汽修（总店）"）vs CRM 户名（如"华泰汽车维修有限公司"）→ `bind_remark` 留痕说明。
3. **解绑即物理删除**：本期不留绑定历史（业务确认）；CRM 侧 1:1 由 `uk_partner_id` 唯一键保证，高德侧 1:N 由应用层校验（`amap_customer_id` 普通索引）。

### 3.2 绑定流程（M8）

```
未关联池选客户 ──► GET /api/visit/relations/suggest（名称相似度+地址距离推荐）
      │
      ▼
POST /api/visit/relations { amap_customer_id, partner_id, bind_remark }
      │ 后端校验：
      │   1. partner_id 在 partner_list 中仍存在（防每周刷新失效）
      │   2. 该 CRM 客户未被其他高德客户绑定（CRM 侧 1:1，uk_partner_id 兜底）
      │   3. 该 CRM 客户未与当前高德客户重复绑定（搜索接口已排除，此处服务端兜底）
      ▼
同一事务：
   upsert visit_customer_relation（同一对幂等更新、新对插入，1:N 追加式）
   update visit_amap_customer.status = 1
```

### 3.3 解绑流程

```
DELETE /api/visit/relations/<amap_customer_id>
   同一事务：
      物理删除绑定行（不留历史）
      visit_amap_customer.status 回置 0（回到未关联池，仅当该高德客户已无任何绑定时）
```

解绑后该客户回到未关联池，可随时重新绑定（插入新行）。

### 3.4 场景矩阵

| 场景 | 操作路径 | 依赖约束 |
| --- | --- | --- |
| 同一对（高德+CRM）解绑后重新绑定 | 直接新增一行（旧行已删，无历史包袱） | 应用层按对幂等 |
| 高德客户追加关联另一个 CRM 客户 | 直接新增一行（1:N 追加式） | `idx_amap_customer_id` |
| 同一对（高德+CRM）重复绑定 | 幂等更新操作人/备注，不重复建行 | 应用层 upsert |
| 两个高德客户绑同一个 CRM 客户 | 拒绝，返回冲突提示 | `uk_partner_id`（CRM 客户侧 1:1） |
| 绑定时 CRM 客户已不存在 | 拒绝，提示重新选择 | `partner_id` 存在性校验 |

### 3.5 唯一约束设计

绑定表只存当前状态、解绑即删行，因此**不需要生成列**，约束设计如下：

- `uk_partner_id (partner_id)`：唯一键，一个 CRM 客户最多被一个高德客户绑定（CRM 侧 1:1）
- `idx_amap_customer_id (amap_customer_id)`：普通索引，一条高德客户可绑定多条 CRM 客户（高德侧 1:N，防重复靠应用层同对幂等）

并发绑定的兜底由 `uk_partner_id` 唯一键承担。

### 3.6 典型查询模式

| 查询 | 走的索引 |
| --- | --- |
| 由高德客户找绑定的全部 CRM 客户（详情页/拜访同步带出 partner_id 列表） | `idx_amap_customer_id` |
| 由 CRM 客户找高德客户（订单匹配反查） | `uk_partner_id` |
| 绑定前冲突预检 | `uk_partner_id` + 同对查询 |

## 四、涉及接口汇总

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/visit/sync/amap_customer` | 高德客户同步（Token 鉴权，幂等） |
| GET | `/api/visit/amap-customers/unbound` | 未关联 CRM 客户池（status=0） |
| PUT | `/api/visit/amap-customers/<amap_poi_id>` | 编辑高德客户档案 |
| GET | `/api/visit/relations/suggest` | 绑定推荐（名称相似度 + 地址距离） |
| POST | `/api/visit/relations` | 绑定 |
| DELETE | `/api/visit/relations/<amap_customer_id>` | 解绑 |

## 五、风险与注意事项

1. **`partner_id` 存在性校验**：`partner_list` 每周二 07:00 全量刷新可能删除客户，绑定/详情展示前必须校验仍存在；发现失效绑定要给出"重新绑定"引导，不能让详情页指标静默取空。
2. **字符集差异**：`partner_list` 是 `utf8mb4_general_ci`，本模块两表是 `utf8mb4_unicode_ci`；字符串 JOIN/比较需显式 `COLLATE`，关联一律优先走 `partner_id`（INT）。
3. **并发绑定**：两个后台同时绑同一客户，应用层预检可能同时通过 → 靠 `uk_partner_id` 数据库兜底，捕获 Duplicate entry 后返回友好提示。
4. **手工客户的同步盲区**：`MANUAL_` 伪编码客户不在高德采集范围内（同步按真实 POI 幂等），只能后台维护，注意告知业务边界。
5. **status=2 无效客户**：不进未关联池、不可绑定；是否允许"恢复为未关联"由业务确认。
