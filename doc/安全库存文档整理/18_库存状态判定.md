# 库存状态判定

> 代码实现：`app/services/stock_safe_service/stock_safe_compute_service.py` 的 `_determine_status` 函数。

## 一、设计思路

采用**数字编码双标签**系统，从两个独立维度判断库存健康度，分别存储在独立的数据库字段中：

- **销售状态（sales_status）**：基于年销量，反映产品市场活跃度（4个等级）
- **库存状态（stock_status）**：基于可销售天数 vs 动态阈值，反映库存量是否合理（6个等级）

两个维度独立判定、独立存储，前端组合显示为 `{销售状态} + {库存状态}`。

## 二、编码规则

### 销售状态（sales_status 字段）

| 编码 | 中文标签 | 触发条件 |
|------|---------|---------|
| 1 | 无销售 | annual_sales_1y == 0 |
| 2 | 销量极低 | 1 <= annual_sales_1y <= 20 |
| 3 | 销量低 | 20 < annual_sales_1y <= 104 |
| 4 | 销量正常 | annual_sales_1y > 104 |

### 库存状态（stock_status 字段）

| 编码 | 中文标签 | 触发条件 |
|------|---------|---------|
| 1 | 呆滞清库 | 可销售天数 >= 补货周期+订货周期+30 |
| 2 | 慢动销去库 | 可销售天数 >= 补货周期+订货周期+10 |
| 3 | 库存积压 | 可用库存 >= 库存上限 × 1.3 |
| 4 | 需补货 | 可用库存 <= 库存下限 |
| 5 | 需补货|可卖天数较少 | 可用库存 <= 库存下限 且 可销售天数 <= 3 |
| 6 | 紧急补货 | 可用库存 <= 安全库存 |
| 7 | 库存正常 | 以上均不满足 |

## 三、动态阈值公式

基于**补货周期 + 订货周期**计算每个产品的个性化阈值：

```
慢动销阈值(天) = 补货周期(LEAD_TIME) + 订货周期(cover) + 10
呆滞阈值(天)   = 补货周期(LEAD_TIME) + 订货周期(cover) + 30
```

### 各 ABC 类别的阈值

| 类别 | 补货周期 | 订货周期 | 慢动销阈值 | 呆滞阈值 |
|------|---------|---------|-----------|---------|
| A类 | 1天 | 20天 | 31天 | 51天 |
| B类 | 1天 | 15天 | 26天 | 46天 |
| C类 | 1天 | 5天 | 16天 | 36天 |

## 四、库存状态判定优先级

按严重程度从高到低：

1. 呆滞清库（可销售天数远超补货周期+订货周期+30天，编码=1）
2. 慢动销去库（可销售天数超过补货周期+订货周期+10天，编码=2）
3. 库存积压（可用库存超过库存上限的1.3倍，编码=3）
4. 需补货（库存降至再订货点以下，编码=4）
5. 紧急补货（安全库存已耗尽，需立即补货，编码=5）
6. 库存正常（编码=6）

## 六、判定逻辑伪代码

```
# ── 销售状态码 ──
if annual == 0:
    sales_code = '1'  # 无销售
elif annual <= 20:
    sales_code = '2'  # 销量极低
elif annual <= 104:
    sales_code = '3'  # 销量低
else:
    sales_code = '4'  # 销量正常

# ── 库存状态码 ──
cycle_days = LEAD_TIME + cover
sellable_days = avail / avg_daily  (if avg_daily > 0 else 0)

if avg_daily > 0 and sellable_days >= cycle_days + 30:
    stock_code = '1'  # 呆滞清库
elif avg_daily > 0 and sellable_days >= cycle_days + 10:
    stock_code = '2'  # 慢动销去库
elif avail >= upper * 1.3:
    stock_code = '3'  # 库存积压
elif sellable_days <= 3 and avail <= lower:
    stock_code = '5'  # 需补货|可卖天数较少
elif avail <= lower:
    stock_code = '4'  # 需补货
elif avail <= safety:
    stock_code = '6'  # 紧急补货
else:
    stock_code = '7'  # 库存正常

# 返回元组，分别存储到 sales_status 和 stock_status 字段
return (sales_code, stock_code)
```

## 七、数据库存储

两个状态分别存储在独立的字段中：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `sales_status` | VARCHAR(20) | 销售状态编码：1=无销售/2=销量极低/3=销量低/4=销量正常 |
| `stock_status` | VARCHAR(20) | 库存状态编码：1=呆滞清库/2=慢动销去库/3=库存积压/4=需补货/5=需补货|可卖天数较少/6=紧急补货/7=库存正常 |

## 八、前后端协作

### 后端查询筛选

库存状态与销售状态均使用**直接字段匹配**：

- `stock_status` 参数：`WHERE stock_status = '需补货|可卖天数较少'`
- `sales_status` 参数：`WHERE sales_status = '无销售'`

### 前端展示

- **表格单元格**：`renderStatusCell` 分别读取 `data.sales_status` 和 `data.stock_status`，映射为中文标签（含「需补货|可卖天数较少」）套用高亮样式
- **统计卡片**：后端 `get_status_count` 分别按 `sales_status` 和 `stock_status` 字段分组统计
- **筛选**：双下拉框分别选择销售状态和库存状态，后端按完全匹配
