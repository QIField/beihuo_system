# 库存状态判定

> 代码实现：`app/services/stock_safe_service/stock_safe_compute_service.py` 的 `_determine_status` 函数。

## 一、核心状态

按优先级从高到低排列，共6种：

| 核心状态 | 触发条件 | 说明 |
|---------|---------|------|
| 呆滞清库 | annual_sales_1y == 0 | 一年无销售，清库处理 |
| 慢动销去库 | annual_sales_1y <= 12 | 月均销量 ≤ 1，逐步去库存 |
| 紧急补货 | avail == 0 或 avail <= safety_stock | 安全库存已耗尽，立即补货 |
| 需补货 | avail <= stock_lower_limit | 库存降至再订货点 |
| 库存积压 | avail >= upper × 1.3 | 库存远超目标上限 |
| 正常 | 以上均不满足 | 库存健康 |

## 二、判定逻辑伪代码

```
if annual == 0:
    status = "呆滞清库"
elif annual <= 12:
    status = "慢动销去库"
elif avail == 0 or avail <= safety:
    status = "紧急补货"
elif avail <= lower:
    status = "需补货"
elif avail >= upper * 1.3:
    status = "库存积压"
else:
    status = "正常"
```

## 三、上下限调整策略

根据库存状态调整上下限：

| 库存状态 | 调整后下限 | 调整后上限 |
|---------|-----------|-----------|
| 正常/紧急补货/需补货/库存积压 | 原始计算值 | 原始计算值 |
| 慢动销去库 | 0 | avail × 0.5（只出不进） |
| 呆滞清库 | 0 | 0（清库） |

调整逻辑：`stock_safe_compute_service.py` 的 `_adjust_limits` 函数。
