# 退货关联表结构（stock_safe_refund_ref）

> 以程序实际 DDL 为准（`sql/stock_safe/stock_safe_refund_ref.sql`）。
> 建立常规订单（order_type_id=1）与退货订单（order_type_id=2）的关联关系，支持多对多匹配。

## 一、字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT UNSIGNED, PK, AUTO_INCREMENT | 主键ID |
| normal_order_items_id | INT | 常规订单明细ID（sales_order_history.orders_items_id），未匹配时为NULL |
| refund_order_items_id | INT, NOT NULL | 退货订单明细ID（sales_order_history.orders_items_id） |
| number | VARCHAR(255) | OE号（与 sales_order_history.number 同名） |
| brand_name | VARCHAR(255) | 品牌名 |
| pdname | VARCHAR(255) | 产品名称（与 sales_order_history.pdname 同名） |
| frey_no | VARCHAR(255) | 条码（与 sales_order_history.frey_no 同名） |
| customer_id | INT | 客户ID |
| normal_quantity | INT | 常规订单数量 |
| refund_quantity | INT | 退货订单数量 |
| refund_create_date | INT | 退货订单创建时间戳（sales_order_history.create_date） |
| processed_quantity | INT | 处理数量（常规订单 quantity + 退货订单 quantity） |
| match_count | INT, DEFAULT 0 | 匹配次数（同一订单多次匹配时递增，查询最新状态取 MAX） |
| type | SMALLINT | 类型编码（见第三节） |
| created_at | DATETIME | 数据创建时间 |
| updated_at | DATETIME | 数据更新时间 |

> **注意**：本表不含价格相关字段（product_price、normal_total_price、refund_total_price、processed_price 均已移除）。

## 二、索引设计

| 索引名 | 类型 | 字段 | 用途 |
|--------|------|------|------|
| PRIMARY | 主键 | id | 主键 |
| uk_normal_refund | 唯一 | normal_order_items_id, refund_order_items_id | 同一(常规,退货)组合唯一，支持一对多 |
| idx_customer_id | 普通 | customer_id | 按客户筛选 |
| idx_number | 普通 | number | 按OE号筛选 |
| idx_type | 普通 | type | 按类型筛选 |
| idx_created_at | 普通 | created_at | 按时间筛选 |
| idx_match_count | 普通 | match_count | 匹配次数查询 |
| idx_normal_match | 复合 | normal_order_items_id, match_count | 加速 MAX(match_count) 子查询 |
| idx_refund_match | 复合 | refund_order_items_id, match_count | 加速 MAX(match_count) 子查询 |
| idx_match_refund | 复合 | customer_id, frey_no(50), number(60), brand_name(50), type, refund_create_date | 匹配查询优化 |
| idx_order_type_date | 复合 | type, refund_create_date | 类型+时间查询 |
| idx_normal_type | 复合 | normal_order_items_id, type | 加速 NOT EXISTS 子查询 |

## 三、type 字段编码规则

两位数编码：十位=匹配状态，个位=匹配模式。

| type | 含义 | 触发条件 |
|------|------|---------|
| 11 | 完全退货（一对一） | processed_quantity=0，一对一匹配 |
| 12 | 完全退货（一对多-常规视角） | processed_quantity=0，常规订单被多条退货分摊完 |
| 13 | 完全退货（一对多-退货视角） | processed_quantity=0，退货订单分摊到多条常规订单后用完 |
| 21 | 部分退货（一对一） | processed_quantity>0，常规订单有剩余 |
| 22 | 部分退货（一对多-常规视角） | processed_quantity>0，常规订单被多条退货分摊后仍有剩余 |
| 23 | 部分退货（一对多-退货视角） | processed_quantity>0，退货订单分摊后常规仍有剩余 |
| 31 | 退货数量超出（一对一） | processed_quantity<0，一对一匹配 |
| 32 | 退货数量超出（一对多-常规视角） | processed_quantity<0，一对多匹配 |
| 33 | 退货数量超出（一对多-退货视角） | processed_quantity<0，退货订单仍有剩余 |
| 40 | 未匹配（第一次） | step2 匹配未找到常规订单 |
| 41 | 未匹配（第二次） | step3 仍未匹配到 |
| 50 | 未进行匹配 | 新入库退货订单，待 step2 处理 |

### 匹配状态编码（十位）

| 十位 | 状态 | processed_quantity |
|------|------|-------------------|
| 1 | 完全退货 | = 0 |
| 2 | 部分退货 | > 0 |
| 3 | 退货数量超出 | < 0 |
| 4 | 未匹配 | — |
| 5 | 未进行匹配 | — |

### 匹配模式编码（个位）

| 个位 | 模式 |
|------|------|
| 1 | 一对一匹配 |
| 2 | 一对多-常规订单视角 |
| 3 | 一对多-退货订单视角 |

## 四、sales_order_history 辅助索引

```sql
-- 复合索引：优化 find_matching_normal_orders 按 customer_id 匹配路径
ALTER TABLE sales_order_history ADD INDEX idx_normal_cid (
    order_type_id, number(60), customer_id, brand_name(50), pdname(80), frey_no(30), create_date
);
-- 复合索引：优化 find_matching_normal_orders 按 fullname 兜底匹配路径
ALTER TABLE sales_order_history ADD INDEX idx_normal_name (
    order_type_id, number(60), fullname(50), brand_name(50), pdname(80), frey_no(30), create_date
);
```
