# 数据关系与同步流程

## 一、整体数据流向

```
┌──────────────────────────┐         ┌──────────────────────────────┐
│   sales_order_history    │         │    stock_safe_refund_ref     │
│   (CRM订单明细，爬虫入库)  │         │   (退货关联匹配表)            │
├──────────────────────────┤         ├──────────────────────────────┤
│ orders_items_id (PK)     │         │ normal_order_items_id ───────┼─┐
│ order_type_id (1=常规)   │         │ refund_order_items_id        │ │
│ number (OE号)            │         │ number / brand_name         │ │
│ brand_name / pdname      │         │ processed_quantity           │ │
│ frey_no / quantity       │         │ type (11~13/21~23/31~33/40~50)│ │
│ create_date (时间戳)     │         │ match_count                  │ │
└───────────┬──────────────┘         └──────────────┬───────────────┘ │
            │ 第一部分：无退货常规订单  │ 第二部分：type=21/22          │
            │ quantity                 │ 最新match_count的pq           │
            └───────────┬──────────────┘──────────────┘                │
                        ▼                                              │
            ┌─────────────────────────┐                                │
            │    oe_parts_sales       │  1:1 (by number, brand_name) │
            │    (销量表)             │◄───────────────────────────────┘
            │ avg_daily_sales_1y      │
            │ sales_std_dev_1y        │
            │ monthly_sales_json      │
            └────────────┬────────────┘
                         │ 同步 avg_daily_sales + 计算
                         ▼
            ┌─────────────────────────┐
            │      stock_safe         │
            │   (安全库存表)           │
            │ abc_classification      │
            │ safety_stock            │
            │ stock_lower/upper_limit │
            │ available_stock ◄─外部  │
            │ sellable_days / status  │
            └────────────┬────────────┘
                         ▼
                  前端展示 / 预警
```

## 二、关联关系说明

- **销量表数据来源**：`sales_order_history`（无退货常规订单 quantity）+ `stock_safe_refund_ref`（type=21/22 最新记录 processed_quantity），按 (number, brand_name) 聚合
- **退货关联**：`stock_safe_refund_ref.normal_order_items_id` 关联 `sales_order_history.orders_items_id`，用于排除有退货记录的常规订单
- **销量表 ↔ 安全库存表**：通过 (number, brand_name) 建立 1:1 关联，均为 `uk_number_brand` 唯一键
- **无物理外键**：各表通过应用层维护关联，避免采集与计算任务相互阻塞

## 三、每日同步流程

```
[CRM系统] ──爬虫──► sales_order_history（订单明细）
                      │
[退货匹配任务] ──► stock_safe_refund_ref（退货关联，Step1/2/3）
                      │
              销量计算任务（按 number+brand_name 聚合净销量）
                ├─ 读取 sales_order_history：无退货常规订单 quantity
                └─ 读取 stock_safe_refund_ref：type=21/22 最新 processed_quantity
                      │
                      ▼
               oe_parts_sales（销量表，净销量统计）
                      │
              安全库存计算任务
                ├─ 同步 avg_daily_sales
                ├─ 读取 sales_std_dev_1y / monthly_sales_json / avg_monthly_sales_1y
                ├─ 读取 abc_classification（决定Z系数/覆盖天数）
                └─ 计算 base/adjusted safety_stock、上下限
                      │
[外部库存系统] ──同步──► available_stock
                      │
                      ▼
               计算 sellable_days / stock_status
                      │
                      ▼
               stock_safe（安全库存表）──► 前端展示 / 预警
```

## 四、每日刷新时序

```
03:00  oe_parts_sales 刷新（销量表）
         │ 依赖退货匹配任务已完成
         ▼
03:45  stock_safe 刷新（安全库存表）
         │ 依赖销量表 + 外部 available_stock
         ▼
04:00  完成，前端可查询最新库存状态
```

## 五、关键约束

- 销量计算任务必须在退货匹配任务（Step1/2/3）完成后执行
- 安全库存表刷新必须在销量表刷新完成后执行
- 两表均每日全量重写（清空后重新写入）
