# 销量表生成流程（oe_parts_sales）

> 每日定时全量重写：DB端聚合 + pandas派生 + TRUNCATE写入。
> 代码入口：`app/services/stock_safe_service/build_oe_parts_sales_service.py` 的 `run_sync()`。

## 一、调度方式

建议使用 `LightweightTaskManager` 注册定时任务，凌晨 3:00 执行，需在退货匹配任务完成后执行。

## 二、执行流程

### 阶段1：DB端聚合抽取（fetch_aggregated_sales）

单次 SQL 完成"合并 + 分组 + 条件聚合"，直接输出 SKU 维度结果：

- `UNION ALL` 合并两部分数据源：
  - 第一部分：`sales_order_history` order_type_id=1，排除已退货订单（NOT EXISTS type IN 11~33），取 quantity
  - 第二部分：`stock_safe_refund_ref` type=21/22 最新 match_count 的 processed_quantity
- `GROUP BY number, brand_name` 按 SKU 聚合
- `SUM(CASE WHEN ...)` 一次性计算年/月/周维度销量列
- 数据质量过滤下推至 WHERE（空值、净销量≤0、时间窗口过滤）

### 阶段2：pandas 向量化派生（_derive_fields）

DB 聚合结果转 DataFrame，向量化计算：

- `avg_daily_sales_1y` = annual_sales_1y / 实际天数
- `avg_monthly_sales_1y` = annual_sales_1y / 12
- `sales_std_dev_1y` = np.std(week_1~52, ddof=0)（52周总体标准差）
- `monthly_sales_json` / `weekly_sales_json` = JSON 序列化
- `stat_date` = 上月最后一天
- 删除 month_1~12、week_1~52 中间列

### 阶段3：TRUNCATE + 批量写入

1. `TRUNCATE TABLE oe_parts_sales`（DDL，隐式提交，不可回滚）
2. `batch_insert(records, batch_size=2000)`——executemany 分批插入
3. 无备份/恢复机制，无防并发状态检测

## 三、异常处理

- 任何阶段异常：记录日志后重新抛出，由上层调用方处理
- 无备份表恢复、无重试机制、无告警推送
