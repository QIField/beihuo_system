### 🏗️ 架构设计说明

#### 一、RBAC3 三层架构核心设计

```
┌─────────────────────────────────────────────────────────────┐
│                      RBAC3 三层架构                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   第一层：用户层 (User)                                      │
│   └── crmapp_users 表                                       │
│       └── 用户身份标识（username, password, is_admin 等）     │
│                                                             │
│   ↓ 多对多关联 ↓                                             │
│                                                             │
│   第二层：角色层 (Role)                                      │
│   └── crmapp_roles 表                                       │
│       ├── 角色基本信息（role_name, role_code）               │
│       ├── 角色层级关系（parent_role_id，支持角色继承）         │
│       └── 8个预设角色（超级管理员、门店管理员、业务经理等）     │
│                                                             │
│   ↓ 多对多关联 ↓                                             │
│                                                             │
│   第三层：权限层 (Permission)                                │
│   └── crmapp_permissions 表                                 │
│       ├── 模块权限（type=1，如购物车模块、单据模块）           │
│       ├── 操作权限（type=2，如 cart:delete, order:process）   │
│       └── 45个预设权限（覆盖8个业务模块）                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 二、核心表结构详解

| 表名 | 核心字段 | 设计说明 |
|------|---------|---------|
| **crmapp_roles** | id, role_name, role_code, parent_role_id, status | 角色定义表，支持角色继承（通过 parent_role_id） |
| **crmapp_permissions** | id, permission_name, permission_code, type, parent_permission_id | 权限定义表，按模块分类，支持通配符权限 |
| **crmapp_user_roles** | id, user_id, role_id, start_time, end_time, status | 用户-角色多对多关联表，支持角色有效期控制 |
| **crmapp_role_permissions** | id, role_id, permission_id, status | 角色-权限多对多关联表 |

#### 三、权限编码规范

```
权限编码格式：模块:操作:资源
示例：
├── module:cart                    → 购物车模块权限
├── cart:view                      → 查看购物车
├── cart:delete                    → 删除购物车
├── order:process                  → 处理单据
├── inquiry:*                      → 询价模块所有权限
└── *:*                            → 所有权限（通配符）
```

| super_admin | 超级管理员 | 所有权限 | 系统管理员 |
| store_admin | 门店管理员 | 所有业务模块权限 | 门店负责人 |
| business_manager | 业务经理 | 业务相关模块全部权限 | 业务部门经理 |
| business_supervisor | 业务主管 | 业务操作权限（继承父角色） | 业务主管 |
| business_staff | 业务员 | 基础业务操作权限 | 普通业务员 |
| market_manager | 市场经理 | 询价、比价模块权限 | 市场部门经理 |
| logistics_manager | 后勤经理 | 单据处理、CRM产品管理权限 | 后勤部门经理 |
| read_only | 只读用户 | 所有模块的查看权限 | 访客用户 |

### 🔄 权限验证流程设计

```
用户登录 → 获取用户信息
    ↓
查询 crmapp_user_roles → 获取用户分配的角色列表
    ↓
过滤：检查角色状态、生效时间范围
    ↓
递归查询 crmapp_roles → 获取角色及其所有父角色（实现角色继承）
    ↓
查询 crmapp_role_permissions → 获取所有角色的权限列表
    ↓
权限去重、合并 → 用户最终权限集合（Permission Codes）
    ↓
缓存到 Redis（可选，提升性能）
    ↓
接口调用时检查权限：
    ├─ 前端：根据权限集合控制按钮/菜单显示
    └─ 后端：在接口层校验权限编码，实现强权限控制
```

#### 3. 权限装饰器设计

```python
# 建议在装饰器层实现接口权限控制

def require_permission(permission_code: str):
    """
    权限检查装饰器，用于接口层
    示例:
        @require_permission('cart:delete')
        def delete_cart_item(...):
            pass
    """
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            # 从请求中获取 user_id
            user_id = get_current_user_id()
            
            # 检查权限
            if not PermissionService.has_permission(user_id, permission_code):
                raise PermissionDeniedException("权限不足")
            
            return func(*args, **kwargs)
        return wrapper
    return decorator
```
