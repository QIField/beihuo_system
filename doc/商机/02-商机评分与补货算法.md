# 商机评分与补货算法

## 一、评分体系概述

商机评分采用 **多维度加权求和** 模型，满分 100 分：

| 维度 | 权重 | 字段 | 核心含义 |
|------|------|------|----------|
| 询价热度 | 40% | `inquiry_score` | 这款配件最近被问得多不多 |
| 缺货强度 | 30% | `out_of_stock_score` | 问了之后缺货的比例高不高 |
| 客户广度 | 20% | `customer_score` | 问这款配件的客户够不够分散 |
| 需求趋势 | 10% | `trend_score` | 询价量是否在上涨 |

设计思路：询价热度是核心信号；缺货强度直接反映供给缺口；客户广度避免单个客户反复询价造成的虚假热度；趋势用于识别上升期产品。

## 二、P80 分位数

P80（第 80 百分位数）是打分的基准线。

**计算方法：**
1. 取全部 OE 码的某个指标值（如近 30 天询价次数）
2. 从小到大排序
3. 取排在 80% 位置的数值

**为什么用 P80 而不是最大值？**
- 最大值容易被极端值拉偏
- P80 能稳定代表“优秀线”，超过即视为高分

代码实现采用线性插值法：

```python
def _percentile(values, pct):
    if not values:
        return 0.0
    sorted_vals = sorted(values)
    n = len(sorted_vals)
    if n == 1:
        return float(sorted_vals[0])
    k = (n - 1) * pct
    f = math.floor(k)
    c = math.ceil(k)
    if f == c:
        return float(sorted_vals[int(k)])
    return float(sorted_vals[f] * (c - k) + sorted_vals[c] * (k - f))
```

## 三、各维度评分公式

### 3.1 询价热度分 `inquiry_score`

```
inquiry_score = min(100, inquiry_count_30d / P80_inquiry * 100)
```

- 达到 P80 询价次数：100 分
- 只有 P80 一半：50 分
- 超过 P80 也只取 100 分

### 3.2 缺货强度分 `out_of_stock_score`

```
out_of_stock_score = out_of_stock_rate_30d * 100
```

- 缺货率 0%：0 分
- 缺货率 50%：50 分
- 缺货率 100%：100 分

### 3.3 客户广度分 `customer_score`

```
customer_score = min(100, customer_count_30d / P80_customer * 100)
```

逻辑与 `inquiry_score` 相同，只是把“询价次数”换成“询价客户去重数”。

### 3.4 需求趋势分 `trend_score`

比较近 30 天与上一个 30 天的询价量变化：

```python
if inquiry_count_prev_30d == 0:
    trend_score = 100.0 if inquiry_count_30d > 0 else 0.0
else:
    rate = (inquiry_count_30d - inquiry_count_prev_30d) / inquiry_count_prev_30d
    if rate <= 0:
        trend_score = 0.0
    else:
        trend_score = min(100.0, rate * 100)
```

- 环比上涨 50%：50 分
- 环比翻倍：100 分
- 环比不变或下降：0 分（只奖励增长，不惩罚下降）

## 四、综合商机评分

```
opportunity_score =
    0.4 * inquiry_score
  + 0.3 * out_of_stock_score
  + 0.2 * customer_score
  + 0.1 * trend_score
```

结果保留两位小数。

## 五、商机等级划分

| 等级 | 分数区间 | 含义 | 建议动作 |
|------|----------|------|----------|
| S | ≥ 80 | 极高价值商机 | 重点跟进，优先备货 |
| A | 60 ~ 79 | 高价值商机 | 关注库存，主动营销 |
| B | 40 ~ 59 | 中等商机 | 保持关注 |
| C | 20 ~ 39 | 低价值商机 | 观察即可 |
| D | < 20 | 无明显商机 | 暂不处理 |

## 六、补货建议算法

### 6.1 核心公式

```
日均询价数 = inquiry_count_30d / 30
建议备货量 = 日均询价数 × 询价转化系数 × 备货天数
建议补货数量 = max(0, 建议备货量 - 当前可用库存 - 在途数量)
```

### 6.2 当前参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `INQUIRY_CONVERSION_RATE` | 0.3 | 询价转化系数，经验值 |
| `STOCK_DAYS` | 15 | 备货天数 |
| `REPLENISH_STOCK_RATIO` | 0.5 | 触发补货的库存阈值比例 |
| `HIGH_OOS_RATE` | 0.5 | 高缺货率阈值 |
| `MIN_INQUIRY_FOR_OOS` | 3 | 触发高缺货补货的最小询价次数 |

### 6.3 触发条件

满足以下任一条件即给出补货建议：

1. `opportunity_score >= 60` 且 `available_stock < suggested_stock_qty * 0.5`
2. `out_of_stock_rate_30d >= 0.5` 且 `inquiry_count_30d >= 3`

未触发时，`replenish_suggestion` 记为 0。

## 七、完整计算示例

假设某 OE 码数据如下：

- `inquiry_count_30d` = 30
- `customer_count_30d` = 8
- `out_of_stock_rate_30d` = 0.4
- `inquiry_count_prev_30d` = 20

全局 P80 基准：

- `P80_inquiry` = 25
- `P80_customer` = 10

计算过程：

```
inquiry_score = min(100, 30 / 25 * 100) = 100
out_of_stock_score = 0.4 * 100 = 40
customer_score = min(100, 8 / 10 * 100) = 80
trend_score = min(100, (30 - 20) / 20 * 100) = 50

opportunity_score = 0.4 * 100 + 0.3 * 40 + 0.2 * 80 + 0.1 * 50 = 77.00
```

最终等级为 **A**（77 分 >= 60）。
