# 商机模块总体设计

## 一、模块定位

商机模块是**安全库存模块的补充**：

| 模块 | 视角 | 核心问题 | 数据来源 |
|------|------|----------|----------|
| 安全库存 | 供给侧（我有什么） | 库存够不够，要不要补 | 销售历史 + 当前库存 |
| 商机模块 | 需求侧（客户要什么） | 哪些配件问得多、缺货多，有潜在销售机会 | 微信询价记录 + 当前库存 |

**设计原则：**
- 不替换安全库存的补货逻辑
- 有独立的轻量级补货建议机制
- 可复用安全库存的当前库存数据（`crmapp_beihuo`），但不依赖其计算结果

## 二、数据来源

### 2.1 主数据源

#### `wechat_daily_quote_detail` — 微信日报报价详情

| 字段 | 用途 |
|------|------|
| `oe_code` | 产品维度核心键，商机聚合维度 |
| `part_name` | 配件名称（取最近一条询价记录冗余） |
| `inquiry_customer` | 询价客户名称，用于客户去重统计 |
| `is_out_of_stock` | 是否缺货，缺货商机核心指标 |
| `create_date` | 询价时间，用于 30 天 / 60 天窗口统计 |

### 2.2 库存数据源

#### `crmapp_beihuo` — 库存快照

| 字段 | 用途 |
|------|------|
| `oe` | 与 `wechat_daily_quote_detail.oe_code` 关联 |
| `库存数量` | 当前可用库存 |
| `在途数量` | 在途数量 |

## 四、核心数据表

### `niche_opportunity` — 商机结果表

每日全量刷新，以 `(oe_code, stat_date)` 为业务唯一键。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增 |
| `oe_code` | VARCHAR(255) | OE 码（产品标识） |
| `part_name` | VARCHAR(255) | 配件名称（取最近一条询价记录） |
| `inquiry_count_30d` | INT | 近 30 天询价次数 |
| `inquiry_count_prev_30d` | INT | 上一个 30 天询价次数（用于趋势） |
| `inquiry_trend_rate` | DECIMAL(6,4) | 询价趋势增长率 |
| `out_of_stock_count_30d` | INT | 近 30 天缺货次数 |
| `out_of_stock_rate_30d` | DECIMAL(5,4) | 近 30 天缺货率 |
| `customer_count_30d` | INT | 近 30 天询价客户去重数 |
| `inquiry_score` | DECIMAL(6,2) | 询价热度分（0~100） |
| `out_of_stock_score` | DECIMAL(6,2) | 缺货强度分（0~100） |
| `customer_score` | DECIMAL(6,2) | 客户广度分（0~100） |
| `trend_score` | DECIMAL(6,2) | 需求趋势分（0~100） |
| `opportunity_score` | DECIMAL(6,2) | 综合商机评分（0~100） |
| `opportunity_level` | VARCHAR(10) | 商机等级（S/A/B/C/D） |
| `available_stock` | INT | 当前可用库存 |
| `transit_quantity` | INT | 在途数量 |
| `suggested_stock_qty` | DECIMAL(10,2) | 建议备货量 |
| `replenish_suggestion` | INT | 建议补货数量（0 表示无需补货） |
| `stat_date` | VARCHAR(20) | 统计日期（YYYY-MM-DD） |
| `created_at` / `updated_at` | DATETIME | 创建/更新时间 |

## 五、API 概览

接口统一注册在 `/new/api/niche` 下：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/list` | GET | 商机列表（分页、筛选、排序） |
| `/summary` | GET | 商机统计摘要（各等级数量、补货建议数） |
| `/top` | GET | Top N 商机 |

> 注：`/export_replenish` 与 `/trigger_compute` 已下线。

## 六、刷新机制

- **频率**：每日全量刷新
- **入口**：`opportunity_compute_service.run_compute(stat_date)`
- **策略**：`TRUNCATE` 清空 `niche_opportunity` 表后批量写入新结果
- **自动刷新**：每日凌晨 2:00 由 `app.scripts.tasks.niche_task` 自动执行（先爬取前 3 天 OE 搜索日志，再计算商机）

## 七、后续可扩展方向

1. **成交率维度**：`deal_status` 数据可用后，可加入成交潜力分
2. **品牌维度商机**：按品牌汇总，辅助品牌引入决策
3. **客户等级加权**：高等级客户询价权重更高
4. **区域/业务员维度**：按群或业务员分析商机分布
