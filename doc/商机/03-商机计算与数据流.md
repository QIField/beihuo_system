# 商机计算与数据流

## 一、当前数据流

商机计算直接读取微信询价原始明细，不再经过统一询价中间层：

```
wechat_daily_quote_detail  ──>  niche_opportunity
        │                              │
        │                              ▼
        │                       crmapp_beihuo
        │                       (可用库存 / 在途数量)
        ▼
   STR_TO_DATE(create_date)
   兼容日期与时间两种格式
```

## 二、计算流程

入口：`opportunity_compute_service.run_compute(stat_date)`

| 阶段 | 操作 | 说明 |
|------|------|------|
| 1 | 读取询价统计 | 从 `wechat_daily_quote_detail` 聚合近 30 天 / 上一个 30 天数据 |
| 2 | 读取库存数据 | 从 `crmapp_beihuo` 批量查询对应 OE 码的库存与在途 |
| 3 | 计算 P80 分位数 | 作为询价热度分与客户广度分的基准线 |
| 4 | 逐行计算 | 评分、等级、补货建议 |
| 5 | 写入结果 | `TRUNCATE` 清空 `niche_opportunity` 后批量写入 |

## 三、SQL 聚合说明

### 3.1 `fetch_inquiry_stats`

按 OE 码聚合近 60 天数据：

- **近 30 天窗口**：`stat_date` 往前 29 天 ~ `stat_date` 当天
- **上一个 30 天窗口**：`stat_date` 往前 59 天 ~ 30 天
- 过滤条件：`oe_code` 不为空、不为 `''`、不为 `'0'`
- 聚合字段：
  - `inquiry_count_30d`：询价次数
  - `out_of_stock_count_30d`：缺货次数
  - `customer_count_30d`：`inquiry_customer` 去重数
- `part_name` 取该 OE 码最近一条询价记录

### 3.2 日期格式兼容

`wechat_daily_quote_detail.create_date` 为 `VARCHAR`，需通过 `CASE WHEN create_date LIKE '% %'` 兼容两种格式：

```sql
CASE
    WHEN create_date LIKE '% %' THEN STR_TO_DATE(create_date, '%Y-%m-%d %H:%i:%s')
    ELSE STR_TO_DATE(create_date, '%Y-%m-%d')
END AS create_dt
```

### 3.3 `fetch_inventory_map`

按 OE 码汇总 `crmapp_beihuo` 的库存和在途：

```sql
SELECT
    oe COLLATE utf8mb4_unicode_ci AS oe_code,
    COALESCE(SUM(`库存数量`), 0) AS available_stock,
    COALESCE(SUM(`在途数量`), 0) AS transit_quantity
FROM crmapp_beihuo
WHERE oe IN (...)
GROUP BY oe COLLATE utf8mb4_unicode_ci
```

## 四、全量刷新策略

- 每天执行一次全量计算
- 先 `TRUNCATE TABLE niche_opportunity`，再批量插入新结果
- 批量插入每批 2000 条，使用 `INSERT IGNORE` 避免唯一键冲突
- 由 `app.scripts.tasks.niche_task` 每日凌晨 2:00 自动执行（先爬取前 3 天 OE 搜索日志，再计算商机）

## 五、历史变更说明

### 去掉统一询价中间层

早期设计考虑过增加 `unified_inquiry_detail` 表作为多渠道询价聚合层，以便未来接入电话、APP、官网等渠道。

经业务确认，当前及可预见未来**只有微信询价一个渠道**，表层面解耦收益不大，反而增加同步耗时和数据一致性风险，因此已移除：

- `app/services/niche_services/unified_inquiry_sync_service.py`
- `app/dao/niche_dao/unified_inquiry_detail_dao.py`
- `app/models/orm_models/niche/unified_inquiry_detail.py`
- `sql/niche/unified_inquiry_detail.sql`

商机计算改为直接读取 `wechat_daily_quote_detail`。

## 六、性能与索引建议

### 6.1 当前索引

`wechat_daily_quote_detail` 已有：

- `idx_create_date (create_date)`
- `idx_oe_code (oe_code)`

### 6.2 优化建议

由于 `create_date` 是 `VARCHAR` 且带函数转换，单独索引效果有限。若性能不足，可在 MySQL 8.0.13+ 考虑函数索引：

```sql
ALTER TABLE wechat_daily_quote_detail
ADD INDEX idx_oe_parsed_date (oe_code, (STR_TO_DATE(create_date, '%Y-%m-%d %H:%i:%s')));
```

或在必要时将 `create_date` 改为 `DATETIME` 类型。
