# 开思对账自动化 —— 使用文档

本目录包含两套独立但对账逻辑互补的自动化流程，用于处理「开思平台」与「金蝶云星空（K3Cloud）」之间的应收对账，并通过 Selenium + pyautogui 模拟人工在金蝶界面下推收款单/收款退款单。

| 流程         | 对账脚本           | 下推脚本       | 适用场景                              |
| ---------- | -------------- | ---------- | --------------------------------- |
| 流程 A：通用对账  | `生成对账Excel.py` | `下推收款单.py` | 开思电子对账单 vs 金蝶应收单，按行 1:1 对账，下推全部差额 |
| 流程 B：开思券对账 | `开思券对账.py`     | `开思券下推.py` | 以开思券账单为主表，仅下推「只缺开思卷」的订单           |

***

## 一、环境准备

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

依赖项：pandas、openpyxl、selenium、pyautogui、pyperclip。

### 2. 浏览器与屏幕要求（重要）

- **Chrome 浏览器 + 对应版本 ChromeDriver**。若 chromedriver 不在系统 PATH 中，需在脚本中配置 `CHROMEDRIVER_PATH`（可通过 `where chromedriver.exe` 查询）。
- **分辨率必须为 1920×1080**（且 100% 缩放）。下推脚本中大量使用 pyautogui 硬编码坐标，分辨率/缩放/浏览器布局变化会导致点击错位。
- 脚本启动时会自动**全屏**打开 Chrome，并在启动前强制结束残留的 chrome/chromedriver 进程（`KILL_STALE_PROCESSES = True`）。

### 3. 运行时注意事项

- 下推脚本运行期间**不要移动鼠标、不要操作键盘**，全程由 pyautogui 模拟人工点击。
- 运行前请关闭可能抢占焦点的窗口。
- 登录账号、金蝶 URL 已在脚本头部 `DEFAULT_K3_URL / DEFAULT_USERNAME / DEFAULT_PASSWORD` 中配置，如需变更请直接修改脚本。

## 二、流程 A：通用对账 + 下推收款单

### 步骤 1：放置输入文件

将以下 Excel 文件放入**本目录**（脚本按关键字/前缀自动匹配，支持带时间戳的文件名）：

| 文件              | 说明                           | 列名位置            |
| --------------- | ---------------------------- | --------------- |
| `开思电子对账单*.xlsx` | 开思平台导出的电子对账单                 | 第 5 行（前 4 行为抬头） |
| `订单结算明细*.xlsx`  | 开思订单结算明细                     | 第 1 行           |
| `应收单*.xlsx`     | 金蝶应收单「按列表引出」文件               | 第 1 行（末行合计自动剔除） |
| `FZD*.xlsx`     | 供应商账单/开思券明细，用于生成「开思卷明细」sheet | 第 6 行           |

### 步骤 2：生成对账 Excel

```bash
python 生成对账Excel.py
```

- 输出到 `data/开思对账_行合并_时间戳.xlsx`，包含 5 个 sheet：
  - **对账结果**：以开思电子对账单为主表，每行标注状态；
  - **模拟点击数据源**：状态为「正常」的行，是下推脚本的输入；
  - **开思卷明细**：有开思券订单的券明细行（需 FZD 供应商账单）；
  - **开思人工核对**：状态异常的开思行，需人工处理；
  - **金蝶人工核对**：金蝶侧需人工处理的行。

### 步骤 3：设置收款单业务日期并下推

打开 [下推收款单.py](下推收款单.py)，修改文件底部的业务日期：

```python
if __name__ == "__main__":
    skd_date = "2026/10/22"   # ← 改为目标业务日期
    run_v5_automation(skd_date=skd_date)
```

然后运行：

```bash
python 下推收款单.py
```

脚本会自动：登录金蝶 → 进入应收单列表 → 逐单按「单据编号-金蝶」搜索 → 下推收款单（金额>0）或收款退款单（金额<0）→ 填业务日期、结算方式（电汇）、银行账号 → 保存 → 回写状态。

- **银行账号自动选择**：发票类型为「无需发票/不开票」→ 无需发票账户；其余 → 已开票账户。
- **断点续跑**：每单成功后立即回写「是否模拟点击状态 = 已写入金蝶」到 Excel；重跑时自动跳过已完成行。
- **异常恢复**：连续跳过 10 条自动重启浏览器重新加载，最多重启 3 次。
- 状态为「完全核销」「除开思卷完全核销」的单据无需下推，脚本会自动校验并跳过。

## 三、流程 B：开思券对账 + 下推

适用于有开思券账单的场景：以券账单为主表聚合，按订单号关联电子对账单和结算明细，再按（客户代码 + 价税合计）与应收单严格 1:1 配对。

### 步骤 1：放置输入文件

| 文件              | 说明        | 列名位置  |
| --------------- | --------- | ----- |
| `开思券账单*.xlsx`   | 开思券账单（主表） | 第 1 行 |
| `开思电子对账单*.xlsx` | 开思电子对账单   | 第 5 行 |
| `订单结算明细*.xlsx`  | 订单结算明细    | 第 1 行 |
| `应收单*.xlsx`     | 金蝶应收单     | 第 1 行 |

### 步骤 2：生成开思券对账 Excel

```bash
python 开思券对账.py
```

- 输出到 `data/开思券对账_时间戳.xlsx`，包含 sheet：
  - **开思券对账**（主表）：含开思税金（= 应收金额 − 对账单开思劵）与对账状态；
  - **金蝶写入数据源**（仅当存在「只缺开思卷」行时生成）。

对账状态说明：

| 状态    | 含义               | 后续处理                |
| ----- | ---------------- | ------------------- |
| 完全核销  | 金蝶已收款 = 价税合计     | 无需处理                |
| 只缺开思卷 | 金蝶已收款 = 价税合计 − 券 | 进入「金蝶写入数据源」，由下推脚本处理 |
| 未收款   | 金蝶已收款 ≈ 0        | 人工处理                |
| 人工核对  | 部分收款或未匹配到应收单     | 人工处理                |

### 步骤 3：设置业务日期并下推

打开 [开思券下推.py](开思券下推.py)，修改底部业务日期后运行：

```bash
python 开思券下推.py
```

脚本读取最新「开思券对账\_\*.xlsx」的「金蝶写入数据源」sheet，逐单按开思券金额正负判断下推方向：**正数 → 收款单，负数 → 收款退款单**（源单剩余金额即开思券，金蝶自动填明细，脚本只填业务日期和银行账号）。成功后回写「是否写入金蝶 = 已写入金蝶」，支持断点续跑。

## 五、常见问题

1. **报错「找不到输入文件」**：确认对应 Excel 已放入本目录，且文件名含有关键字（如「开思电子对账单」「应收单」「FZD」）。
2. **报错「缺少字段」**：导出文件格式与脚本预期列名不符，按报错中列出的实际列核对来源系统导出的字段。
3. **浏览器启动失败（DevToolsActivePort）**：脚本已自动排除该问题（清理残留进程 + excludeSwitches）；仍失败时先手动关闭所有 Chrome 再重跑。
4. **下推点击位置不对**：检查分辨率是否为 1920×1080、浏览器是否被脚本全屏启动；必要时用 `test.py` 重新标定坐标。
5. **中断后想继续**：直接重新运行下推脚本即可，已标记「已写入金蝶」的行会自动跳过。
6. **生成的对账 Excel 在哪**：统一输出到本目录下 `data/` 子目录，文件名带时间戳，不会覆盖历史结果。
